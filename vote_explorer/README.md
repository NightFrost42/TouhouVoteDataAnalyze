# 东方人气投票数据查询器

这是一个离线桌面工具，数据范围为中国区 CN1–11 与日本区 JP3–22。CN10、CN11 的角色、曲子和 CP/组合榜已纳入；数据已经随程序放在 `data/` 目录，不需要联网。

## 直接运行

在 Windows 上双击 `启动投票分析工具.bat`。电脑需要安装标准版 Python 3.10+（安装时勾选 **Add Python to PATH**）；Tkinter 是标准库的一部分，不需要额外安装绘图库。

如果程序没有打开，会显示错误弹窗并在本目录生成 `launcher_error.log`。也可以双击 `debug_launch.bat` 运行诊断版，命令窗口会保留错误信息，不会闪退。

Tkinter 不是普通的 pip 包。Windows 的 python.org 标准安装版已经自带 Tkinter；WSL/Ubuntu 开发环境可用 `sudo apt-get install python3-tk` 安装。本项目当前 WSL 环境已安装并验证 Tk 8.6。

界面支持：

- 地区、届次、榜单类别筛选；
- 中文名/日文名/实体 ID 模糊搜索；
- 积分、实体总票数/选择人数、加权分、排名、第一顺位/本命票切换；
- 当前榜单柱状图、实体历届趋势图、有效投票总量趋势图；
- CP/组合投票结果排行，以及所有可用组合的两届哑铃对比；有官方 CP 项目的届次使用官方结果，没有官方 CP 项目的届次自动使用同投人数，并在结果表标注“同投替代”；
- 导出筛选结果 CSV 和当前图表 SVG（可用浏览器、Inkscape、Illustrator 或 PowerPoint 打开）；
- 表格双击一行即可把实体名带入搜索框。

点击主窗口的“打开文章分析工作台”，可以进入参考文章同类的模板化分析界面。当前工作台内置 72 个模板，当前届与对比届可从 CN1–11、JP3–22 的全部实际届次中任选。模板覆盖：任意两届独立系列比较、角色/曲子的“届数 × 官方名次”变化图、同地区全部届次趋势、角色名次变化、3/2/1 与等权/2/1 规则对照、第一/第二顺位率、实际选择人数与选择率、跨届增长、顺位结构、角色性别画像、曲子指标排行/任意两届对比/全部届次趋势/第一顺位率、角色—曲子交叉分析、曲子投票 × 同人曲数量、角色投票 × 关联原曲同人曲数量、同投人数/方向同投率/集中倍数/人气基准/φ 分数/四象限/网络/矩阵、跨部门与音乐内部两套同投集中聚类、CP/组合排行与跨届哑铃对比，以及 CN2–4 详情群体统计、CN5–11 条件榜和 JP17–22 已公开的逐实体问卷。所有真正的双指标交叉模板固定使用散点图（可切换到数据表），不会退化成单变量条形图。缺少某项公开数据时会保留为空并说明原因，不会伪装成有效指标。

参考文章中的几类专用图形已经单独实现：多指标列内排名热力图、带未公开斜线格和异常橙框的方向同投率矩阵、共同人数 × 集中倍数 × φ 气泡图、四个代表阵营的分面网络、两届同投人数哑铃图，以及“问卷答案选项 × 比例”的两届哑铃图。顺位结构会按届次实际公开字段自动选择三段（第一/第二/其余）或两段（第一/非第一，旧届未细分第二顺位），不会把缺失的第二顺位伪装成 0。问卷下拉框会列出数据中实际公开的问题，某届没有该题时留空而不是按 0 处理。

“问卷关联”和“曲子问卷关联”模板会把逐实体问卷与投票结果直接连接。可以选择性别、年龄、入坑时间、历届投票经验或线下活动参与，再选择具体问卷选项，并用名次、分数、实际选择人数、第一顺位率等作为投票指标。现有三类关联分析：投票指标 × 问卷比例散点图、相对全体的问卷倾向排行、每个问卷选项与投票指标的皮尔逊相关系数。相关系数用于发现关系，不代表因果。新增“角色人气 × 关联曲人气”和“曲子人气 × 所属角色人气”两个交叉散点图，关系来自独立的 `analysis_character_music_links_all.csv` 打标表。中文区与日文区的题目、选项和原始文案按届次分别保留；两地区合并查看时，即使译名相同也会在结果表中标出原文，避免把不同问卷误并为一个选项。

“曲子投票 × 同人曲数量”同时使用 `data_raw/thwiki_music/original_song_arrangement_counts_jp_vote_windows.csv`（JP3–22）和 `original_song_arrangement_counts_cn_vote_windows.csv`（CN2–11）的独立投票结束日历，绝不会因届次编号相同而套用另一地区的数据。横轴可选择三种整数口径：届间新增数 `arrangement_count`、截至该届投票结束（发布日期不晚于投票结束日）的累计数 `arrangement_cumulative_count`、以及抓取时点总表中的累计总数 `arrangement_total_count`。CN1/JP3 是首届基线，前两种口径为空，仅抓取时点总数可用；早期届次若只公布官方分数，指标下拉会自动回退到分数。最后一种是 2026-09-04 的快照，包含投票结束后的新增，不能当作当届历史存量；未标日期曲目不纳入历史累计并单列。角色交叉图会按角色—原曲 canonical key 去重后汇总所选口径，并在表格中同时列出三种合计与未标日期数量。交叉图的计数坐标轴只显示整数，屏幕和 SVG 导出均保留右侧边距，避免末端刻度或标签被截断。

问卷关联模板新增“最少实体投票人数”筛选（默认 0 表示不筛）。阈值使用同一地区/届次实体投票中的 `selection_count`，而不是问卷选项人数；设置为正数时，低于阈值或缺失实体投票人数的角色/曲子不会参与散点、倾向、相关和矩阵计算，并在图下注明过滤口径。

问卷关联散点图严格区分“人数”和“比例”：横轴是实际选择该问卷选项的人数，纵轴是该实体支持者/听众中选择该选项的比例，点大小和结果表中的“问卷有效人数”表示分母规模。因此比例高不等于人数最多，阅读时应同时看横轴、纵轴和有效样本数；不同角色的投票总数不会被误当作问卷关联的横轴。

CN10/11 现代问卷的比例分母使用官网 `totalAnswers`。题目和答案下拉框按地区、届次及实体类别动态生成：CN 使用当届中文问卷原题，JP 使用当届日文问卷结构，同名但来源不同的题不会互相覆盖。年龄图保留官网实际分段，不能无损对齐的 CN/JP 年龄段分行显示。CN5–11 条件榜中的交叉人数按 `交叉人数/实体总选择人数` 还原为 `P(问卷选项|实体)`，再与全体选项比例计算百分点差，不把接口原始的反向条件率 `P(实体|问卷选项)` 当作实体画像。入坑时间题统一映射为 `cognition`，届次未提供的选项保持空白。

工作台的“图表类型”只显示当前模板支持的类型，避免把不适合的数据误画成分组条或堆叠图；可配置指标也会按当前届、对比届实际有数据的字段动态筛选，避免隐藏的旧指标造成空图。两届同一实体默认用哑铃图；多届趋势用折线；结构比例用 100% 堆叠；连续指标关系用散点；同投关系可用矩阵、网络或气泡图。变化排行可切换“全部变化 / 只看正数变化 / 只看负数变化”，并在各自方向内排序。还可以调整 Top N、起止名次、同投最少人数、搜索条件、当前/对比届、排序、配色、名称语言、是否显示标签/网格、导出宽高和自定义横纵轴。指标和问卷下拉框均显示中文名。

“跨部门同投集中聚类”和“音乐内部同投集中聚类”分成两个模板。两者都使用可审计的单链接规则：共同人数达到阈值且 `lift≥1.20` 的边进入图；以连通分量成簇，聚类得分为 `Σ max(0, observed−observed/lift)`。跨部门角色×曲子覆盖 CN10–11、JP17–22，使用 `P(音乐|角色且参与音乐部门)/P(音乐)`，不要求角色榜与音乐榜总票数相同；音乐内部完整矩阵覆盖 CN10–11。没有对应矩阵的届次留空，不用其他关系冒充。

“分段总览（非作图）”页可直接按 1–20、21–40、41–60、61–80、81–100、全部或任意自定义起止名次浏览完整角色名，并有上一段、下一段和区间 CSV 导出。区间会同时影响图表、分段总览、计算结果表、SVG 和 CSV；同投关系可选择“两端都在区间”或“至少一端在区间”。关系网络用编号节点和完整名称清单，长名字在表格和导出中不会截断。

工作台现在提供“原作阵营”筛选。前四项固定为参考图中的红魔馆、地灵殿、秘封俱乐部、神灵庙，随后列出博丽神社、白玉楼、永远亭、守矢神社、命莲寺、妖怪之山、天界、地狱、畜生界、月之都、魔界、妖精、外界等原作群体；角色可同时属于多个群体。另有“作品首登：……”选项，表示 THBWiki 首次登场作品 cohort，不把同作品角色误称为同一组织。映射表和来源见 `data/analysis_character_factions.csv`，未能核对一设群体的角色保留在“未分类”，不会用社区标签补齐。选择阵营后，角色/同投图按阵营成员过滤，曲子图按已打标的角色—曲子关系过滤。

所有届数×指标折线图均为观测点之间的直线连接，缺失届次保留断点，不使用平滑曲线或插值。

折线图会在每个届次位置绘制淡色竖向辅助线；鼠标悬浮或点击观测点/线段时，会显示对应的系列名称、届次和实际指标值，并以蓝色竖线标出当前届次位置。

散点、气泡和哑铃图同样支持悬浮/点击提示；哑铃图在每行右侧显示“当前届 − 对比届”的差值。切换届次、指标或问卷选项时会清除旧提示。问卷选项统一按中文显示（作品/入坑时间沿用发布时间顺序，无法对应的原文保留在数据表中）。

## 构建可发送的 Windows 版本

有两种打包方式，都不要求接收者安装 Python。

构建过程中产生的 `build/`、`dist/`、`.build_python/`、`.build_tcl/`、`.build_tk/`、`.pyinstaller_vendor/`、`*.spec` 和 `*.zip` 均为本机临时或发布文件，已经加入根目录 `.gitignore`，不会作为源代码提交。需要发送给别人时，只发送压缩后的目录版或单文件 EXE；源码仓库只保留构建脚本和程序源文件。

超过 GitHub 单文件限制的问卷和同投表会在构建末尾自动切成约 80 MB 的分卷；每卷都有表头，查询器启动时会自动合并读取。需要手工处理时，可在项目根目录运行 `python scripts_pipeline/split_large_files.py --all --replace` 分卷，或运行 `python scripts_pipeline/split_large_files.py --all --merge` 恢复完整文件。

### 目录版（推荐日常更新数据）

在 Windows 上双击 `build_windows.bat`。脚本会重建最新数据、检查 Tkinter、安装 PyInstaller（如果尚未安装），然后生成：

```text
dist/TouhouVoteExplorer/TouhouVoteExplorer.exe
dist/TouhouVoteExplorer/data/...
```

把整个 `dist/TouhouVoteExplorer` 文件夹压缩后发给别人即可。不要只复制这个 EXE；运行库位于 `_internal`，数据位于 EXE 同级的 `data` 文件夹。

目录版的优点是以后只更新数据时不必重新打包程序：双击 `build_analysis_data.bat` 后，脚本除了更新源码目录的 `data`，还会自动把新数据同步到已经存在的 `dist/TouhouVoteExplorer/data`。同步结束后重新压缩整个目录即可。为了兼容此前已经生成的旧目录版，它也会在旧版 `_internal/data` 存在时同步一份；重新运行一次 `build_windows.bat` 后便会采用新的同级 `data` 布局。

### 单文件版（只发一个 EXE）

在 Windows 上双击 `build_windows_single.bat`，会生成：

```text
dist/single_file/TouhouVoteExplorer_Portable.exe
```

这个 EXE 已经把当前 `data` 目录完整嵌入，可以单独发送，接收者直接双击即可。单文件版每次启动时会由 PyInstaller 把运行库和数据临时解压，因此启动通常比目录版稍慢；数据有更新时必须重新运行 `build_windows_single.bat`，否则 EXE 内仍是旧数据。

如果单文件 EXE 旁边另外放置一个完整的 `data` 文件夹，程序会优先读取这个外部目录。这可用于临时替换数据；移走该目录后会恢复使用 EXE 内嵌数据。

构建脚本会检查 Tkinter，并在 Python 3.14 等将 Tcl/Tk 脚本库放入 ZIP 的版本中自动展开 Tcl/Tk 资源，避免单文件 EXE 启动后因找不到 Tk 库而闪退。若只想在自己的电脑上使用，直接运行 BAT 即可。

分析工作台需要先生成便携分析表；如果目录中没有这些文件，先在项目根目录运行：

```text
python scripts_pipeline/build_vote_explorer_analysis_data.py
```

Windows 用户也可以双击 `build_analysis_data.bat`。该脚本只读取已经爬取的本地文件，不会联网；它只重建和同步数据，不会把修改后的 Python 程序代码写入旧 EXE。程序代码有变化时仍需重新运行对应的 Windows 构建脚本。

构建完成后可用以下方式检查输出是否完整：目录版应同时存在 `TouhouVoteExplorer.exe`、`_internal/` 和同级 `data/`；单文件版只需检查 `TouhouVoteExplorer_Portable.exe` 能启动。若只更新了数据，运行 `build_analysis_data.bat` 后重新压缩目录版即可；若修改了 Python 程序代码，必须重新运行对应的完整构建脚本。

## 数据说明

`data/rankings.csv` 是 33,533 行统一长表，`data/ballot_totals.csv` 是 94 行有效票数汇总；字段、来源与计分制度差异请见 `data/DATASET_README.md`。CN 与 JP、不同届次之间的积分规则并不完全一致，跨届比较时建议优先看名次、票数或票占比，并结合来源说明。

附加分析表还包括 `analysis_questionnaire_all.csv`（CN1–11 静态/现代总体问卷与 JP17–22）、`analysis_entity_questionnaire_all.csv.gz`（CN2–4 详情群体统计、CN5–11 官方问卷条件与 JP17–22 逐实体问卷）、`analysis_cn_advanced_pairs_all.csv.gz`（CN5–11 官方问卷交叉）、`analysis_cp_metrics_all.csv`（官方 CP/组合榜）和 `analysis_vote_combinations_all.csv`（官方 CP 与同投替代统一组合表），以及 `cn_alignment_audit.csv`（投票榜与详情的未匹配审计）。CN1 没有逐实体群体详情；CN2–4 的公开统计来自详情页而非后期 API，manifest 会分别记录来源。CN10/11 的普通榜和已爬取的现代 GraphQL 数据已纳入；若某届没有官方 CP 项目，组合表会明确使用同投替代，而不会伪装成官方 CP。
