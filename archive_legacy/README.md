# 历史归档说明

这里保存从主工作区移出的旧程序、旧输出和诊断证据。它们不属于当前维护流水线，但没有被当作垃圾直接删除。

## 内容

- `invalid_analyses/`：已确认不能支持原结论的退化分析输出。
- `tag_analysis_v1/`：旧 Wiki 标签/文本分析程序、输入缓存和输出；当前以官方数值流水线为主。
- `monolithic_vote_json_v1/`：旧单体 `touhou_vote.json` 数据模型及生成/统计程序；补充问卷不完整，且已知日方 gender 男/女字段为空。
- `vote_plotting_v1/`：已被当前可复算流程取代的旧绘图与早期规范化程序。
- `network_diagnostics/`：小型 HTTP 诊断证据，其中保留的 `.tmp_cn_*` 文件是归档记录，不是待恢复的根目录缓存。
- `environment_py311_broken/`：已删除的损坏虚拟环境依赖版本清单。
- `vote_datasets/votes_cn1-9_jp3-21/`：旧版 CN1–9 / JP3–21 投票数据快照；当前构建使用上一级的 `datasets/votes_cn1-9_jp3-22/`，两者不要混用。

`archive_manifest.csv` 是归档的权威索引，记录每个文件的原路径、归档路径、字节数、SHA-256、原因和替代路径。恢复文件时应按该清单逐项还原并复核哈希，不要整目录覆盖当前主流程。

归档脚本保留的是历史相对路径假设，可能仍指向工作区根目录的工作簿，或会在根目录生成旧输出；它们仅供追溯，不保证可在归档目录内直接运行。

归档目录下的 README 仅供本地追溯，已在根目录 `.gitignore` 中排除；归档数据如需发布，应以 `archive_manifest.csv` 中的哈希和路径为准。
